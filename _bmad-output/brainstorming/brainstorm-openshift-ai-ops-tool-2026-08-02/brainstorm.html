Ecosystem Thinking

Mapping the tool as a living ecosystem — agents, knowledge flows, dependencies, food webs.

Triage Coral

  • Stateless filter between AlertManager and diagnosis agents
  • Deduplicates alert storms, correlates related alerts into single root-cause events
  • Prevents agent drowning during cascades

Orchestrator as Hypothesis Builder

  • Forms initial subsystem hypothesis from alert metadata + runbook context
  • Hybrid dispatch: handles simple alerts solo, spawns specialists only when cross-domain
  • Unique roles: dispatch logic, conflict resolution, completeness quality gate
  • Holds evolving diagnosis state as session coordinator

Domain Specialists

  • Compute, storage, network — extensible by deployment
  • Produce domain-specific diagnosis with confidence levels
  • Feed on: live cluster state (cluster-reader SA) + agentic-skills + runbooks + vector DB
  • Support lateral escalation: specialist refers to another specialist

Food Web Layering

  • Each organism accesses only its layer's knowledge — stays lean
  • Specialists → cluster state + domain skills
  • Orchestrator → specialist outputs + runbooks + vector DB + RHOKP
  • Triage → raw alert stream + grouping rules

Disney Method

Dreamer → Realist → Critic: three lenses on the same system.

Dreamer

  • Predictive mode: pre-alert diagnosis from metric trends, users see 'Prevented' entries
  • Cross-cluster federated learning — collective immune system (deferred)
  • Scoped prediction: propose new PrometheusRules to intercept future trends
  • Dry-run pre-flight: oc apply --dry-run=server, admission checks, RBAC/quota validation

Realist

  • OLM-managed operator → PIVOT: Helm-deployed, no CRDs
  • Rationale: minimize dependencies on the cluster being healed
  • LLM is external concern — configurable URL + credentials, different models per agent role
  • UI: OpenShift Console extension + standalone web app, both via tool's own API

Critic

  • Alert storm handling: dedup via status tracking, priority queue, configurable parallelism cap
  • Remediation serialization: global lock, one at a time, cooldown between actions
  • Rollback: never automatic, human-triggered only, failure stored as negative case
  • LLM reliability: retry with backoff, fallback endpoint, vector DB fast-path bypass

Swarm Logic

Self-organizing specialist claims — no central dispatch, plug-and-play extensibility.

Self-Selecting Specialists

  • Each specialist watches alerts and claims based on label-matching rules
  • Multiple specialists can claim the same alert — orchestrator collects and synthesizes
  • New domains: deploy specialist, it auto-claims matching alerts — zero reconfiguration
  • Binary claim/no-claim (dropped claim confidence — diagnosis confidence is sufficient)

Unclaimed Alert Handling

  • Orchestrator acts as generalist of last resort
  • Flags coverage gap in UI: "no specialist covers this alert type"
  • Signals operational need for new specialist deployment

Queue Management

  • Alerts via webhook, prioritized by urgency × recency
  • Cleanup: explicit 'resolved' webhook for instant dequeue
  • Safety net: TTL-based expiry with AlertManager API verification

Emerging Tech Collision

Force-marrying the tool with frontier tech — what new possibilities emerge?

OpenShift MCP Server

  • Official Red Hat tech preview — Go-native, direct K8s API, no kubectl dependency
  • Two instances: read-only (diagnosis) + read-write (remediation execution)
  • Security boundary enforced at infrastructure level via service accounts
  • Supports --read-only mode, multi-cluster, RBAC-respecting, bearer token auth

Knowledge Graph

  • Causal map of cluster-specific failure patterns — not generic OpenShift
  • Relational: alert X caused by Y which cascades to Z
  • Makes triage smarter with historical causality for THIS cluster

Adversarial Debate Protocol

  • 1 challenge round per diagnosis — stability = pass
  • If diagnosis fundamentally changes → original was bad, new one gets challenged
  • Comparison: structured schema diff (root_cause hash) + embedding fallback for novel failures
  • RBAC airlock: diagnosis becomes immutable artifact before remediation sees it

Key Architectural Decisions

  • Auto-remediation gated by 3D policy matrix: severity × blast_radius × confidence
  • Success criterion: the alert resolves — simple, pragmatic
  • Case records capture successes AND failures with temporal decay
  • Fast-path: high-similarity past case → skip LLM, replay previous fix
  • Remediation plans as structured objects: steps, blast_radius, rollback, risk, preconditions
