## What Went Well

1. **All 5 stories delivered to done** — 100% completion rate
2. **210 tests** (117 unit, 93 integration) — comprehensive safety net covering all stories
3. **Architecture decisions held up** — AD-5 (five-layer correlator), AD-23 (priority queue), AD-19 (state machine), AD-24 (event bus) implemented faithfully
4. **Solid concurrency patterns** — `pg_advisory_xact_lock` for dedup and queue serialization, `FOR UPDATE SKIP LOCKED` for queue dequeue, `FOR UPDATE` on open correlation groups
5. **Foundation is production-grade** — structured JSON logging, audit trail, SSE with replay buffer and `Last-Event-ID` reconnection, structured error envelopes, OpenShift OAuth authentication
6. **Background sealing sweep** — proactive asyncio task seals expired correlation groups without relying on incoming alerts as a trigger
7. **Strong story intelligence chain** — each story built on predecessor context, reducing ramp-up time

## What Didn't Go Well

1. **Review documentation gap** — 19 findings across 4 stories were genuinely fixed in code but left as `[ ]` (unchecked) in story files. This created a false picture of unresolved issues and obscured the actual quality state.
   - Root cause: Neither the review agent nor the fix agent had explicit instructions to update checkboxes when fixes were applied. The base `bmad-code-review` workflow writes findings but doesn't enforce checkbox updates on fix.
   - Impact: Required a manual audit of all 19 findings to verify code state matches documentation.

2. **Excessive review rounds** — Stories 1.0 (8 rounds) and 1.3 (7 rounds) took significantly more review iterations than necessary.
   - Root cause: Fix agents sometimes introduced new findings while fixing old ones, and review scope narrowing to force convergence left some findings unaddressed until later.
   - Mitigation: The review cap (5 rounds max) in `bmad-epic-dev.toml` prevents infinite loops. Remaining findings are documented as deferred debt.

3. **Testcontainers/Podman environment issue** — integration tests failed silently when the Podman socket wasn't configured, with an unhelpful `DockerException` error.
   - Root cause: `testcontainers` library defaults to Docker socket; Podman requires explicit `DOCKER_HOST` and `TESTCONTAINERS_RYUK_DISABLED=true` environment variables, plus `systemctl --user start podman.socket`.
   - Impact: Blocked integration test runs until diagnosed and documented.

4. **Cross-test data leakage** — 3 integration tests made incorrect assumptions about database isolation:
   - `test_firing_webhook_creates_incident_row` asserted `received` state but correlation advances it to `correlating`
   - `test_create_group_with_seed_alert` and `test_add_alert_to_existing_group` used `get_open_groups()` without filtering by group ID, seeing groups from other tests
   - Root cause: Session-scoped PostgreSQL container shares data across tests within the session.

5. **No agent model tracking** — story files didn't record which model performed the review or which model applied fixes, making it impossible to audit the review chain.

## Actions Taken During Retrospective

All of the following were completed and committed during the retrospective session:

### Process Improvements

1. **Created `_bmad/custom/bmad-code-review.toml`** — New team customization with two rules:
   - Rule 1: Code Review Record section with review model + fix model tracking per review round
   - Rule 2: Finding checkbox discipline — `[ ]` to `[x]` immediately on verified fix, `**Fixed**` notes mandatory, re-review checkpoint updates for prior findings
   - `on_complete` gate verifies checkbox-to-code consistency before finalizing

2. **Enhanced `_bmad/custom/bmad-dev-story.toml`** — Added:
   - `persistent_facts`: Dev Agent Record mandatory fields (Agent Model Used, Debug Log, Completion Notes, File List)

3. **Corrected all 19 finding checkboxes** — Verified each finding was fixed in code, updated story files from `[ ]` to `[x]` with explicit `**Fixed**` notes:
   - Story 1.0: 5 findings (docs/OpenAPI routes, Python version, Uvicorn logging, v1 placeholder, PostgreSQL password)

## Key Takeaways

1. **Code review documentation must be treated as seriously as code fixes** — 19 unchecked findings proved that fixing code without updating docs creates a false quality picture
2. **Workflow customization rules are institutional memory** — `bmad-code-review.toml` and `bmad-dev-story.toml` encode lessons so future agents don't repeat mistakes
3. **Test infrastructure gotchas must be documented immediately** — the podman issue would have bitten every future agent
4. **The review cap (5 rounds) is essential** — without it, review cycles can loop indefinitely
