Reviewer: Adversarial

Structural Hole Hunter Fail
Critical
Pipeline-to-SSE event transport unspecified
AD-21 defines event shapes but no delivery mechanism exists between pipeline/ and api/. AD-14's dependency graph has no pipeline/ → api/ path. Two epics (pipeline vs API/UI) will invent incompatible internal transports (in-process bus, Redis pub/sub, polling DB, etc.).
Critical
AD-19 "only pipeline writes state" contradicts API writes
Approval resumption, resolved-webhook cancellation (AD-23), and initial incident creation all require api/ to write state that AD-19 forbids. AD-19 and AD-23 directly contradict each other on who can mutate incident/queue state.
Critical
AD-18 conflates advisory locks and row-level locks
Sentence 1 says "PostgreSQL advisory lock." Sentence 3 says "row-level in a dedicated remediation_locks table." These are mutually exclusive PostgreSQL features. Two epics implementing different sentences will produce two independent locking mechanisms.
High
AD-20 prescribes vector similarity for co-occurrence queries
AD-5 layer 5 needs "which alert fingerprints historically co-occur?" — a discrete set-membership query. AD-20 constrains the correlation layer to "pgvector similarity search," which solves a semantically different problem. Correlation epic and learning-store epic will implement incompatible query interfaces.
High
Per-agent LLM config has two contradictory sources of truth
AD-7 says "configured via Helm values." Conventions table says "Policy matrix and per-agent LLM config are runtime-mutable via API." No merge/override semantics specified — config epic and deployment epic will produce conflicting configuration paths.
Medium
Audit log ownership unspecified
Conventions say "all state-changing operations are audit-logged" — but no AD specifies who writes to the audit log (middleware? per-module? dedicated service?). API epic and pipeline epic may implement duplicate audit writes or miss each other's mutations.
Medium
Evidence artifacts storage location unspecified
AD-4 references "evidence artifacts" in the typed contract, and the Policy Gate blocks on their absence. But no AD specifies whether these are stored inline in the diagnosis object, in a blob store, or as PostgreSQL JSONB. Diagnosis epic and policy-gate epic may diverge.

Recommendation

The spine is architecturally sound in its paradigm and coverage, but has accumulated contradictions — likely from multiple revision rounds — that will break integration if epics proceed independently. An Update pass addressing the 4 critical findings is required before epic decomposition:

  • Reconcile RHOKP: Adopt the spec's Solr + okp-mcp resolution into AD-13 and AD-9 (update pod topology to 7 deployments).
  • Specify pipeline→API event transport: New AD or tighten AD-21 (likely: in-process async queue since backend is one Python process per AD-9).
  • Clarify state-write ownership in AD-19: Define which writes are "pipeline-owned" vs "API-permitted" (approvals, webhook cancellation, incident creation).
  • Fix AD-18 lock semantics: Choose one mechanism (advisory lock OR row-level lock in a table) and state it consistently.

The 5 high findings are important but won't cause hard integration failures — they can be resolved during or immediately after the critical fixes.
